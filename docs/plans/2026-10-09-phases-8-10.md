## Phase 8: Accessibility-first reading + keyboard

1. **Reader preferences.** Schema `Preference`: `readerFont String @default("serif")`, `readerSize Int @default(18)`, `readerLeading Float @default(1.7)`, `readerMeasure Int @default(68)`, `reduceMotion Boolean @default(false)`.
   - Migration `reader_prefs`. Add `parseReader*` clamps with a test to `src/lib/reading/reader-prefs.ts`.
   - The reader page applies them as `style={{'--reader-size': …}}` on `<article>`. `.reader-content` in `globals.css` reads those vars.
   - The settings page gets a font radiogroup, three range inputs with `<output>`, and a live preview paragraph. A small client component updates the CSS vars as the controls move.
   - Commit: "Add reader typography preferences with live preview".
2. **Themes.** Use `next-themes` (`attribute='data-theme'`, themes light / dark / high-contrast, `enableSystem`).
   - In `tokens.css`, the dark media block also matches `[data-theme=dark]`. Add a `[data-theme=high-contrast]` block of AAA tokens (≥ 7:1) and verify the ratios with a small node contrast script in tmp.
   - `prefers-contrast: more` applies the high-contrast tokens when the theme is System. A `ThemeSync` client component sets `data-theme-system` on `<html>` so the CSS can target that case.
   - Add a theme radiogroup to settings.
   - Commit: "Add light, dark, system and high-contrast themes".
3. **Reduce motion.** The app layout sets `data-reduce-motion` on its wrapper when the preference is on. The CSS rule matches the existing `prefers-reduced-motion` block. Add a checkbox in settings. Commit.
4. **Announcer.** `src/components/Announcer.tsx` holds the context, one `aria-live=polite` region and `useAnnounce()`.
   - Replace the ad-hoc status spans in RefreshButton, ItemFeed (new items) and the MarkAllRead toast message (the visible toast stays).
   - Commit: "Centralize screen reader announcements".
5. **Keyboard.** `src/components/Shortcuts.tsx` is mounted in the app layout. It ignores keys while focus is in inputs, textareas, selects, contenteditable elements or an open dialog.
   - In lists:
     - `j`/`k` move a selected index kept in ItemFeed via a context. The selected row gets `aria-selected`, a ring and `scrollIntoView({block:'nearest'})`.
     - `o`/Enter opens the item, `s` toggles saved and `m` toggles read.
   - `g h` / `g s` / `g f` go to /app, /app/saved and /app/feeds. `/` goes to /app/search and focuses its input.
   - `?` opens a `<dialog>` with the shortcut sheet.
   - In the reader, `j`/`k` go to the next/previous article using ReaderNav's links.
   - Commit: "Add keyboard shortcuts and shortcut sheet".
6. **Command palette.** `cmdk` `Command.Dialog` on ⌘/Ctrl-K with these entries:
   - go to a category or feed (from navigation passed down by the layout)
   - Saved, Digest, Search, Settings
   - change layout
   - refresh all
   - Commit.
7. **`/accessibility` statement page**, linked from the app footer and the landing page. Audit `guidance/accessibility.md` and record the result in `docs/accessibility-audit.md`. Mark the VoiceOver pass as "pending a manual run" (I can't run it).
   - Commit.

## Phase 9: AI summarization

1. Add `@anthropic-ai/sdk` and the optional `ANTHROPIC_API_KEY` in `env.ts`. `src/lib/ai.ts` exports `aiEnabled` and `summarize(text)`.
   - **Model call:** `claude-opus-5-5`, `output_config: {effort:'low'}`, and server-side fallback with `betas: ['server-side-fallback-2026-07-01']` and `fallbacks: 'default'`. The system prompt asks for two short plain-text paragraphs with no preamble. Check `stop_reason === 'refusal'` before reading the content.
   - **Before writing:** check the installed SDK's types for the exact param names.
2. **Schema:**
   - `Item.aiSummary String?`
   - `AiUsage(userId, day Date, count Int, @@id([userId, day]))`
   - `DigestBriefing(userId, windowKey, text, createdAt, @@id([userId, windowKey]))`
   - Migration `ai`.
3. **`summarizeItemAction(itemId)`:**
   - Scope the item to the user and return a cached `aiSummary` if there is one.
   - Otherwise check and increment the daily cap atomically (`INSERT … ON CONFLICT DO UPDATE … WHERE count < cap RETURNING`): guests get 5, accounts 50.
   - Convert the HTML to text, call the model and store the result.
   - **Errors:** `RateLimitError` → "Try again in a minute". Other `APIError`s → `{hidden:true}`.
   - **UI:** `AiSummary.tsx` in the reader, with a button, a skeleton and an "AI summary" label. It renders nothing when `!aiEnabled`.
   - Add a test for the cap logic and the refusal/error mapping, with the client injected.
4. **Digest briefing:** one cached paragraph per user per `windowKey` (window + window start ISO), built from the top 20 titles and excerpts. Show it above the groups when AI is enabled. It counts against the same cap. Commit.
